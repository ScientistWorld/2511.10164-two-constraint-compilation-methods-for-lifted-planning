# Hardening report

**Better results now score higher, worse results lower, and every shortcut from the audit (`REDTEAM.md`) is closed: each one now fails the run and gets the worst value in every metric.** This required replacing the gym's design. The old evaluator scored artifacts the method wrote itself: its own compiled tasks for one fixed visible task, its own "valid/invalid" plans, its own ground comparator, and the method keys listed in the train scores. The method now registers a *compiler command*. The evaluator generates the constrained tasks itself (the held-out ones only at test time) and runs every registered compiler on them. It checks that each compiled task accepts exactly the plans the constrained task accepts, and measures the compiled task's size against a ground-first comparator it computes itself.

All numbers below come from actual runs of the unmodified, no-argument `scripts/evaluate_test.sh` / `scripts/evaluate_train.sh` in CPU job `7214d826-e8c`. Raw files: `redteam/hardening/results/` (`scores_test_all.json`, `scores_train_all.json`, `scores_test_empty.json`, `summary.json`, logs). The private-search row comes from job `PRIVATE_SEARCH_JOB`.

**How the ranks are computed.** Each scored metric contributes `weight × |coefficient| × improvement` over `lifted_tcore` in its better direction, divided by the metric's population standard deviation; zero-spread terms add 0. Population **A** is all 16 attempts in the hidden-test run. Population **P** is just the reference and the one attempt.

## What changed

| requirement | before | after |
|---|---|---|
| Test answers and anything that regenerates them live only in `eval/test/` | Tasks and probe plans came from the method's own artifact; test cases were visible. | Tasks, hidden probe plans and exhaustive checks are generated by `eval/test/test_lib.py` (its own seeds), in memory, at test time. The compiler only ever sees one constrained task per call. |
| Evaluator recomputes every number from raw outputs | Counts were recomputed, but the task, goal and expected verdicts came from the method. | Plan verdicts come from the original task and its constraint monitors; sizes come from the returned task; registration fields other than `command` are ignored. |
| Comparison side fixed by `eval/` | The `ground_tcore` comparator was a submitted artifact. | Ground-first sizes are computed analytically from the task. Instance counts, seeds, probe sets, time/memory/size limits and worst values are constants in `eval/`. |
| Failed constraint means failed run; worst values everywhere | Semantic rates were additive rewards; a crash wrote no scores; empty results tied. | Any plan disagreement, crash, timeout (30 s), memory (4 GB) or size (32 MB) breach, malformed output or invalid registration fails the run: worst value in every metric of every experiment (`semantic_agreement` 0, ratio metrics 1.0, formula metrics 7.0). No registration at all writes a `missing_submission` entry with worst values. |
| Test scores every method on disk | Test restricted itself to the methods named in the editable `scores_train.json`. | Test enumerates `outputs/compilers/*.json` and never reads train scores. |
| Brute force must not solve the test | 28³-action grounding passed every check. | Tasks have 20–32 objects and schemas of arity up to 5; full grounding is 1.4×10⁷–4.5×10⁷ actions on average per experiment. |
| Paper's own settings | LiftedTCORE kept updates with R^L(φ,a)=φ, contrary to Section 3.2. | Restored the paper's omission. Constraint variables are renamed apart from action variables, so regression is capture-free. |
| Headroom where the paper falls short | — | New `many_constraints_size` (30–45 constraints per task, the paper's Appendix D limitation). |

**The gate.**
- *Large tasks* (ground, non-ground, many-constraints) are checked on about 23 (51 for many-constraints) hidden plans per task: the witness, goal-reaching plans that violate each constraint, other valid plans, non-goal plans and inapplicable plans.
- *Small tasks* (type suite, edge cases) are checked by complete breadth-first exploration of the product of the original task, its constraint monitors and the compiled task. Generation keeps only small tasks with at most 2,500 reachable state/monitor pairs, so on every small task the check is a full equivalence proof, up to the bounded closure of auxiliary actions.

**Metrics** (five experiments, the same five metrics in each):
- `semantic_agreement`
- `effects_vs_ground_log10` and `actions_vs_ground_log10` (paper Table 3)
- `formula_nodes_log10`
- `max_formula_nodes_log10` (the paper's "largest formula", Section 6.1)

Coefficients: 1.0 / −1.0 / −0.2 / −0.8 / −0.4. Weights: ground and non-ground 0.25 each (the paper's two datasets), type suite 0.20, edge cases 0.15, many-constraints 0.15. The many-constraints weight replaces the dropped single-instance `constraint_semantics` experiment, which is subsumed by the exhaustive suite. Effects carries the largest coefficient because Table 3's effect counts are the paper's headline succinctness claim. Formula size is weighted next because the paper ties formula size to planner performance (LCC's coverage advantage). Actions carry little weight because any exact compiler keeps the input's schemas.

## Do better results score higher?

**Before:** the better Boolean optimizer scored A +0.1115 / P +1.64. The clearly weaker constraint-removal variant scored P **+1.50**, and its A sign depended on which other attempts were present.

**After** (hidden test; train is in parentheses):

| attempt | what it is | rank A | rank P |
|---|---|---:|---:|
| `lifted_tcore_invariant` | **better**: invariant-aware regression (below) + generic Boolean simplification | **+0.0178** (+0.0175) | **+2.40** (+2.40) |
| `lifted_tcore_simplified` | the earlier audit's Boolean optimizer applied to the restored reference | +0.0038 (+0.0032) | +2.20 (+2.40) |
| `lifted_tcore` | reference | 0 | 0 |
| `lifted_tcore_hashseed1/2` | reference compiler under `PYTHONHASHSEED=1/2` | 0 (0) | 0 (0) |
| `lcc` | the paper's second method | −0.0057 (−0.0361) | 0.00 (0.00) |
| `lifted_tcore_no_omission` | **weaker**: the earlier reproduction (no R=φ omission) | **−0.0535** (−0.0638) | **−4.12** (−4.12) |
| `ground_tcore` | ground-first baseline (refuses beyond its 200K ground-action budget) | −6.8034 (−6.8086) | −6.80 (−6.80) |

**Paired per-task comparisons against the reference** (hidden test; every method sees the same tasks; seed noise is exactly 0, because the hash-seed reruns are identical in every metric and generation and compilation are deterministic):

- **Invariant variant.** On every reachable compiled state, `always(φ)` guarantees φ holds now, `¬seen_ψ` guarantees ¬φ for SometimeBefore, and ¬φ is asserted inside the at-most-once guard. Literals fixed by these invariants fold the persistence part f ∧ ¬Γ¬f of the regression to a constant.
  - Formula nodes are lower in all five experiments: mean Δlog10 −0.015 to −0.043, t = −3.1 to −6.4. 60 of 80 tasks are better and none worse.
  - The largest formula is lower in all five: Δ −0.025 to −0.080, t = −2.6 to −4.0.
  - Effects and actions are identical.
  - It passes the complete exhaustive check on all 80 small tasks (train + test) and the probe gate on all 80 large ones.
- **No-omission variant.** Worse in every experiment:
  - effects +0.043 to +0.146 log10 (t = 4.3 to 10.8; 67 of 80 tasks worse, none better);
  - formula nodes +0.028 to +0.070 (t = 3.5 to 10.2).
- **LCC.** More effects (+0.15 to +0.26 log10) and one more action. Smaller formulas: total −0.08 to −0.19, largest −0.27 to −0.54. This is the paper's trade-off (Table 3: LiftedTCORE 58 vs 63 effects; Section 6.1: largest formula 26 vs 18 atoms). Under the coefficients it is balanced (P 0.00) and lands slightly below the reference in A.

**Why rank A values are small.** Population A contains the eight attempts that failed (including the bad registration), each at worst values (e.g. `effects_vs_ground_log10` = 1.0 against about −7 for working compilers). These dominate each metric's spread, so improvements among working compilers become small after normalization. The ordering is unaffected, and population P shows the per-pair margin.

- **Before:** one fixed 28-object task per size regime; 1 action and 7 effects (non-ground: 5) against 21,952 ground actions; all eight semantic rates 1.
- **After** (hidden test, LiftedTCORE; mean per task):

## Headroom check

- **At the bound:**
  - `semantic_agreement` = 1 for the reference in all five experiments. It is the constraint, not a benefit.
  - `actions_vs_ground_log10` is at the practical bound: the reference keeps exactly the input's schemas, and only deleting provably useless schemas could go lower.
- **Not at the bound:** effects, total formula nodes and largest formula.
  - The invariant-aware variant beats the reference on two of these in every experiment, by many paired standard errors.
  - The generic simplifier also beats it, by less.
  - No simple variant reaches a bound.
- **Added experiment:** `many_constraints_size`, where the paper's method falls short. The reference's compiled tasks there carry 147 effects and 2,503 formula nodes (LCC: 266 effects); the invariant variant already trims 8% of the nodes.
- **Baselines:** the ground-first baseline is clearly below (failed, −6.80). The weaker no-omission variant is below the reference by many standard errors, on a scale with room above.

## What I left, and what I could not fix

1. **The probe gate on large tasks is a test, not a proof.** A compiler that is wrong only on trajectories unlike the hidden probes could pass. Mitigations:
   - the small-task check is complete;
   - each constraint has hidden goal-reaching violators;
   - the measured private-search attack failed (table above);
   - `scoring/CONSTRAINTS.md` forbids pruning against sampled trajectories, and the separate grader can see it.

   A stronger attacker that first solves the task, then builds near-miss trajectories of the evaluator's kind, was **not** measured.
2. **In-container access.** At test time a compiler process could read `eval/test/` files from disk. That is not sandboxable inside the container; `scoring/CONSTRAINTS.md` forbids it and the grader can see it.
3. **Planner metrics are not reproduced.** The paper's LAMA coverage, node expansions and runtimes are not reproduced, and wall-clock compile time is not scored. The gym measures exactness and compiled size only. Synthetic random domains replace the IPC-2023 domains. Their randomness makes the generating process impractical to hand-write, and a better compiler on them (smaller, exact) is a better compiler on the paper's problem.
4. **Thin SometimeBefore initial-witness coverage.** The edge-case generator produced only 1 SometimeBefore initial-witness task in the test slice (always-constraints are not targeted there). The type suite covers SometimeBefore in 10 test tasks.
5. **Rank-A compression.** Failed attempts' worst values compress population-A ranks (see above). This comes from the specified normalization, and the ordering is preserved.
6. **Auxiliary actions.** Their interleavings are explored to depth 3 (at most 64 closure states) between consecutive steps. A compiler relying on longer auxiliary chains is checked only up to that bound.
7. **Previous audit material.** `redteam/` outside `redteam/hardening/` is the previous audit of the old design. Its scripts depend on removed files and are kept as evidence only.
